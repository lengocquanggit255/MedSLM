# PharmKG HOP PoLo V7 Final — Setting B

This folder contains one independent, sequential training run. It starts with
raw PharmKG and pinned original public weights, trains a new codebook and all
model stages in the same session, selects checkpoints on validation Hits@1,
reloads the selected checkpoints, and evaluates the official test split once.

## Pipeline

1. Verify hashes of raw PharmKG, original `google/flan-t5-small`, and original
   `sentence-transformers/all-mpnet-base-v2`. Verify the fixed train/validation
   split against `configs/reference_split.json`. Test answer fields remain
   deferred at this point.
2. Create a fresh semantic/structural codebook from the raw KG.
3. Train Flan synthetic `READ_S`/`READ_G`, then the answer-balanced no-G QA SFT
   with executable labels checked at `label_edge_cap=200`.
4. Decode predicted train/validation programs from the selected Flan checkpoint.
5. Train policy warm-up from QA train gold paths, then Setting B from that
   session's selected warm-up checkpoint. Setting B combines teacher edge CE,
   node rank loss, and multi-route marginal path mass under predicted programs.
6. Build the same pre-prune depth-1/2 candidate pool for train and validation;
   train the sole pool ranker from a fresh initialization. The old-score gate
   stays fixed at zero.
7. Reload selected Flan, Setting B policy, and pool-ranker checkpoint bytes;
   lock their hashes; only then load test answers and evaluate test once.

Each training phase allows **24 update epochs**, with **patience 3**. Epoch 0
is evaluated and saved. Validation runs after every update epoch. Selection is
highest validation Hits@1; exact ties choose the earlier epoch. Flan and
policy use the fixed `cold_numeric_score` proxy on their predicted-program
candidate pool. Their proxy scores are not final ranker scores. Recall@20 and
other metrics are reported, but they do not select checkpoints.

## Inputs and isolation

`inputs/` has six raw PharmKG files and local snapshots of the two original
public models. The 22 file hashes and upstream model revisions are in
`inputs/input_manifest.json`. `input_lineage.json` records their staging.
There are no previous PharmKG codebooks, program caches, trained model weights,
or ranker checkpoints in `inputs/`. The entrypoint refuses unexpected input
files or a split differing from `configs/reference_split.json`.

Only QA train answers create labels or update weights. Validation answers are
used to compute checkpoint metrics. Test questions/topics are available for
duplicate filtering and later program decoding; official test answers are
parsed only after all checkpoints have been selected and reloaded.

## Run

With a compatible Python/GPU environment:

```bash
python3 src/hop_polo_v7_final.py \
  --input-root inputs \
  --config configs/full.json \
  --reference-split configs/reference_split.json \
  --source-manifest source_manifest.json \
  --output /path/to/new-empty-run \
  --device cuda
```

The working directory for that command is this folder. The output directory
must be empty. `source_manifest.json` is generated by the packaging command
below; omit `--source-manifest` only for an unpackaged local development run.
The model dependencies follow the V6/V7 source generation. Kaggle's Torch and
NumPy are retained; `kaggle/run.py` pins the text stack without reinstalling
Torch or CUDA.

To make a Kaggle dataset and kernel source bundle without submitting either:

```bash
python3 tools/package_kaggle.py --owner YOUR_KAGGLE_USERNAME
```

This writes `kaggle/package/dataset/` with the source archive, raw/public
input archives and hashes, plus `kaggle/package/kernel/` with the launcher and
kernel metadata. If packaged, the Kaggle launcher runs the same
`src/hop_polo_v7_final.py` entrypoint. No pre-existing PharmKG checkpoint
dataset is referenced. Kaggle publication requires uploading the dataset and
then committing the kernel with the generated metadata; this folder does not
submit automatically.

## Output audit

The run saves the source/input/split manifests, codebook and hashes, QA label
audits, predicted program caches, every epoch checkpoint and history with
validation predictions, candidate diagnostics, selected checkpoint hashes,
final validation metrics, test predictions, test metrics, and an independent
recount from test prediction node IDs. The test count is recorded as one in
`audit.json`. These files are produced by a completed training run; they are
not precomputed in this source folder.

## Replay the earlier Setting B checkpoint through this codebase

The optional `tools/replay_setting_b_checkpoint.py` loads the earlier selected
Setting B Flan, policy and pool ranker into the inference modules in this
folder. It uses the earlier run's matching codebook and predicted test program
cache, because the old policy weights are tied to that codebook. This replay
does not feed any old artifact to the from-scratch training entrypoint.

From the workspace root:

```bash
python3 hop_polo_v7_final/tools/replay_setting_b_checkpoint.py \
  --output hop_polo_v7_final/replay_setting_b
```

The replay compares each qid with the locked Kaggle Setting B test output.
Its full-run result is in `replay_setting_b/verification.json`.
